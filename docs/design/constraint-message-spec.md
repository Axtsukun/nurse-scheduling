# 制約名・メッセージの仕様

診断（解けないときの MUS）や制約の一覧に出す「制約の名前」の仕様。
制約を **ID・制約クラス・クラス名・メッセージ** の4項目で表し、メッセージは **構造化データ（対象・パラメータ）から共通の整形器で作る**。

- 状態: 仕様（案を決定したもの）。実装は `nurse/message.py` ほか。
- 決定の経緯: セッション中に、ID の形式・表示・生成方式・付与範囲を確認して決めた（本文の「決定事項」）。
- 「既定の判断」（9 節）は、未確認のまま既定値を置いた点。直す場合は 8 節の一覧と `nurse/message.py` の1か所を変える。

---

## 1. 目的

CPMpy は制約式に名前を付けられない。診断では、MUS が返す式から「どの制約か」を引き戻して、人が読める形で出す必要がある。
制約の名前に必要な最低限の項目を決め、メッセージは**制約の内容がシンプルに解釈できること**を優先する。

## 2. 制約レコード

| 項目 | 内容 | 例 |
|---|---|---|
| `id` | `{群}-{群内連番}`。全制約でモデル全体で一意 | `cover-0012` |
| `group` | 制約クラス（群）。`@constraint` の登録名 | `cover` |
| `title` | 制約クラス名（日本語・短い。片側の群は方向を含む） | `人数制約下限` |
| `message` | 具体的な内容。対象とパラメータから整形器が作る（診断のときだけ生成） | `11/03 12:30 - 11/03 13:00 勤務者数=10` |
| `target`・`params` | メッセージの元になる構造化データ（6 節） | |
| 内部項目 | 式（`expr`）、背景か（`hard`）、適用範囲、根拠ID。表示しない | |

背景の制約（構造・履歴）と補助変数の定義（`Aux`）には、ID は付くが、`target`・`params`・`message` は空（診断の説明に出ないため）。

## 3. ID

- 形式: `{群}-{群内連番}`。区切りはハイフン、群内連番は **1始まりで4桁ゼロ埋め**（超えたら自然に延ばす）。例: `cover-0012`、`72h-0249`。
- **全制約に付ける**（補助変数の定義・背景の制約を含む）。連番は、その群の制約メソッドが返した順（生成順）。
- 同じ入力（インスタンス・設定）なら同じ ID になる。入力が変わる（固定割当を足す、制約群をオフにする、など）と ID も変わる。
  実行をまたいで同じ制約を指すときは、メッセージ（対象とパラメータ）で対応づける。
- 補助変数の定義にも連番を振るので、診断に出る制約の ID は飛び番になる（例: `72h` は補助変数が先にあるため、本体は `72h-0249`）。連番が詰まっていることは保証しない。

## 4. 表示行

```
{ID}  [{クラス名}] {メッセージ}
```

例: `cover-0012  [人数制約下限] 11/03 12:30 - 11/03 13:00 勤務者数=10`

- ID は**行頭**。ID とクラス名の間は半角スペース2つ。
- ID は一意なので、同じ文面の制約が複数あっても行は集約せず、ID で区別する。

## 5. メッセージの書式

```
<対象> <名前><演算子><値> <名前><演算子><値> …
```

- 文章にせず、対象と、パラメータの「名前=値」を並べる。演算子は既定が `=`。必要なとき（閾値の向きを示すとき）だけ `>=`・`<`・`<=` などを使う。
- **方向（以上・以下・一致）の表し方**:
  - 片側の群は **クラス名**で表す（`人数制約下限`、`連続勤務日数上限`、`公休数一致`）。パラメータは `=`。
  - 両側の群（`night_band`）は、クラス名は方向を含めず（`夜勤回数範囲`）、**パラメータ名に方向を入れる**（`夜勤回数下限=6`、`夜勤回数上限=9`）。
- **単位**: 名前が「〜数」「〜日数」「〜回数」のものは数値のみ（`勤務者数=3`）。時間は `h`（`勤務間隔=11h`、`月平均夜勤時間=72h`）。
- 1行・補足の括弧は付けない。

## 6. 構造化データと整形器

制約メソッドは、式と一緒に **対象（`target`）** と **パラメータ（`params`）** を返す（`Item(式, target, params)`）。整形器（`Renderer`）が `Instance` の表示方針で文字にする。

### 部品（`target` の要素）

| 部品 | 意味 | 表示（開始日あり） | 表示（開始日なし） |
|---|---|---|---|
| `Nurse(n)` | 看護師 | 職員名（未指定なら `N05`） | 同左 |
| `Day(d)` | 計画日（負は履歴） | `MM/DD` | `6日目(土)`（履歴は `前月末2日前`） |
| `DaySpan(d0, d1)` | 日の範囲（両端を含む） | `MM/DD - MM/DD` | `6日目(土) - 11日目(木)` |
| `Span(a, b)` | 時間帯 `[a,b)`（計画日0の0:00を0とするスロット） | `MM/DD HH:mm - MM/DD HH:mm` | `6日目(土) 08:30 - 6日目(土) 17:00` |
| `Cat(k)` | 勤務区分 | 区分名（日勤・準夜・深夜・パート。`Instance` で上書き可） | 同左 |
| `Shift(s)` | 勤務 | 勤務名 | 同左 |
| `Clock(slot)` | 時刻（日をまたぐと48以上） | `HH:mm`、翌日は `翌HH:mm` | 同左 |
| 文字列 | そのまま（`病棟`、`正規` など） | | |

- 時刻は `HH:mm`（**ゼロ埋め**。`08:30`）。
- **時間帯の終わりが24:00のときは、翌日の `00:00`** と書く（例: `11/03 17:00 - 11/04 00:00`）。スロットの絶対位置（`d * 48 + slot`）から日付と時刻を作るので、日またぎ・月末・年末で自然になる。
- 範囲の表記は、開始日の有無によらず、常に両端を書く（`A - B`）。

### パラメータ（`Param`）

`Param(名前, 値, 単位="", 演算子="=")`。値は数値・文字列・上の部品（`Clock`、`Nurse` など）。

## 7. 表示方針の入力（`Instance`）

| 項目 | 型 | 役割 |
|---|---|---|
| `start_date` | `date \| None` | 計画日0の暦の日付。指定したときだけ `MM/DD` 表記になる。未指定なら `N日目(曜)` に戻る |
| `nurse_names` | `list[str] \| None` | 看護師の表示名（職員名・職員ID）。未指定なら `N05` |
| `cat_names` | `dict[str, str]` | 勤務区分名の上書き（二交代の病院など）。未指定の区分は既定の表 |

生成時に検査する: `start_date` を指定したら、その曜日が `start_weekday` と一致すること。`nurse_names` を指定したら、看護師数と同じ長さであること。

## 8. 制約クラス名とメッセージの一覧

メッセージの例は、計画日0を 11/02（月）とした場合（`start_date=2026-11-02`）。

| 群 | クラス名 | メッセージの例 |
|---|---|---|
| `struct` | 勤務一意 | （背景。メッセージなし） |
| `history` | 履歴固定 | （背景。メッセージなし） |
| `fixed` | 固定割当 | `N03 11/07 勤務=日` |
| `holiday` | 休日数下限 | `N03 11/02 - 11/08 休日数=1` |
| `offcount` | 公休数一致 | `N00 公休数=9` |
| `cover` | 人数制約下限 | `11/03 12:30 - 11/03 13:00 勤務者数=10` |
| `skill` | リーダー数下限 | `11/03 準夜 リーダー数=1` |
| `72h` | 夜勤時間平均上限 | `病棟 月平均夜勤時間=72h` |
| `rest` | 勤務間隔下限 | `N00 11/03 - 11/04 勤務間隔=11h 前日終業>=翌00:30 翌日始業<11:30` |
| `consec` | 連続勤務日数上限 | `N03 11/07 - 11/12 連続勤務日数=5` |
| `offblock` | 休み連続日数下限 | `N00 11/03 休み連続日数=2 ブロック長=1` |
| `weekend` | 勤務週末数上限 | `N00 勤務週末数=3` |
| `night_band` | 夜勤回数範囲 | `N00 夜勤回数下限=6` / `N00 夜勤回数上限=9` |
| `weekend_spread` | 土日勤務日数差上限 | `正規 N00 土日勤務日数差=2` |
| `sym_break` | 夜勤回数整列 | `N00 夜勤回数>=N01` |
| `req_off` | 休み要望違反数上限 | `要望数=46 違反数=13` |
| `req_shift` | シフト要望違反数上限 | `要望数=47 違反数=14` |
| `soft_off` | 希望休違反数上限 | `要望数=60 違反数=10` |

## 9. 既定の判断（未確認のまま既定値を置いた点）

1. **両側の群のクラス名**: `night_band` は、クラス名を方向なし（`夜勤回数範囲`）にし、方向はパラメータ名（`夜勤回数下限`・`夜勤回数上限`）で表す。
   `weekend_spread` は下限・上限が1つの「差」を作る2本の式なので、どちらも `土日勤務日数差=2`（同じメッセージ、ID で区別）にする。
2. **ID の飛び番号**: 許容する（3 節）。
3. **クラス名の一覧**: 8 節の案のとおり。
4. **人数制約の時間帯の単位**（ユーザー決定）: メッセージは、**実際に効いている基本区間**（勤務の始業・終業の境で区切った小区間。例: `12:30 - 13:00`）と**勤務者数**の2つだけで表す。
   需要区間（人数を指定する単位）は出さない。シフトのパターンはメッセージに含めず、制約として考慮するのは人数を設定する小区間であることを優先する。
   同じ被覆の基本区間を統合した制約は、統合した区間の最小の始点〜最大の終点を表示する。

## 10. 受け入れ基準（検証すること）

- ID は全制約でモデル全体で一意で、群ごとに `0001` から連続する。形式は `^[0-9A-Za-z]+-\d{4,}$`。
- 全群にクラス名があり、クラス名は群の間で重複しない。診断に出る制約（soft・前提）は、すべてメッセージが空でない。
- 開始日あり・なしの両方で、整形器が 6 節の表のとおりに出す（日またぎ・履歴の日・月をまたぐ場合を含む）。
- 8 節の例が、実装の出力と一致する（開始日あり）。
- 求解用の式は、名前・メッセージの有無で変わらない（変更前後で式のハッシュが一致）。
- `build()` のとき、メッセージ（文字列）は作らない（診断のときだけ生成する）。

| 仕様 | 実装 |
